## Acceptance criteria

- [ ] Object editing separates player-facing text from private GM notes. Supported existing descriptions become GM notes without data loss; initial player text is empty. No automatic prose splitting or implicit publication occurs.
- [ ] Fields management provides a shared player-publication setting for native Atmosphere/Port class and custom Fields. Legacy and newly created Fields default private. Applicability remains a distinct concept and changing it does not erase stored assignments or imply publication.
- [ ] Object editing can additionally mask a value of an otherwise shareable Field. An object mask cannot make a private Field public. Modes below Revealed suppress prose and all Fields regardless of definition/assignment settings.
- [ ] The player preview inspector shows player text and only the name/type/value of Fields actually permitted on Revealed objects. GM notes, masked values, private/unused definitions, applicability inventories and unselected options remain absent from the projection.
- [ ] Publishing a single-select value does not expose other possible values. For example, sharing Faction: Merchants must not embed an unused secret Cult option. Native option lists have the same no-unused-inventory rule.
- [ ] Source publication settings, masks and both prose fields follow normal draft validation, Apply/Discard, save/reload and Undo/Redo. Export/projection does not alter source notes or values.
- [ ] Complete GM backups/imports and current/last-valid recovery preserve all prose, Field definitions, values and publication intent. Independent-copy import remaps definition IDs and object masks correctly. Same-name definition merges preserve compatible policies or require an explicit conflict/review; they never silently broaden publication.
- [ ] Existing legacy layout/applicability/Jump-level support and full-map backup semantics remain intact. Extend the common projection/preview; no separate Field-only sharing format or additional campaign notes subsystem is introduced.
