# Hébergement gratuit — état au 8 octobre 2026

## En bref

Nuxt n'exclut pas GitHub Pages : Pages n'exécute pas le rendu SSR du build actuel, mais Nuxt peut pré-rendre l'application en fichiers statiques. Le projet utilise `ssr: true` et `npm run build` lance `nuxt build` ([nuxt.config.ts](../../nuxt.config.ts), [package.json](../../package.json)); Nuxt 3 propose aussi `nuxt generate` pour la génération statique, même avec le rendu SSR activé.

## Comparatif

| Option | Fonctionnalités utiles | Avantages | Inconvénients / adéquation |
| --- | --- | --- | --- |
| **Vercel Hobby — Nuxt/Nitro SSR** | Détection Nuxt sans configuration, déploiements Git et prévisualisations de branches, domaines personnalisés et fonctions serveur. L'offre gratuite comprend notamment 100 Go de transfert, 1 million de requêtes CDN et 1 million d'invocations de fonctions par mois. [Nuxt sur Vercel](https://nuxt.com/deploy/vercel) · [Plan Hobby et limites](https://vercel.com/docs/plans/hobby) · [Environnements de déploiement](https://vercel.com/docs/deployments/environments) | Conserve le build `nuxt build` et le SSR actuels; déploiement très direct. | Hobby est réservé à un usage personnel non commercial; quotas mensuels. Le SSR n'apporte pas de persistance aux campagnes et n'est pas nécessaire aux fonctionnalités présentes. Bon choix si priorité à la simplicité et si le projet reste personnel. |
| **GitHub Pages — Nuxt statique** | Déploiement statique via GitHub Actions; Nuxt fournit un preset GitHub Pages. Pour l'URL de projet actuelle, configurer `NUXT_APP_BASE_URL=/mothership-tools/`. Domaines personnalisés et HTTPS pris en charge. Un dépôt public est requis sur GitHub Free; la limite souple de bande passante est de 100 Go/mois. [Nuxt 3 — statique](https://nuxt.com/docs/3.x/getting-started/deployment) · [Nuxt sur GitHub Pages](https://nuxt.com/deploy/github-pages) · [Limites GitHub Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/github-pages-limits) | Suffisant pour cette application dans le navigateur et s'intègre directement au dépôt GitHub; aucun serveur à maintenir. | Site publié public, sans SSR ni API serveur. Il faut un build statique et gérer le chemin `/mothership-tools/`; les previews de branches ne sont pas intégrées comme chez Vercel ou Cloudflare Pages. Bon choix pour une publication personnelle simple si le site public convient. |
| **Cloudflare Pages — Nuxt statique** | Offre Free : 500 builds/mois, un build simultané, 20 000 fichiers par site et 25 MiB maximum par fichier. Prévisualisations illimitées et jusqu'à 100 domaines personnalisés par projet. Nuxt peut y être généré statiquement; les Pages Functions sont possibles, avec quotas Workers. [Limites Pages](https://developers.cloudflare.com/pages/platform/limits/) · [Prévisualisations](https://developers.cloudflare.com/pages/configuration/preview-deployments/) · [Domaines personnalisés](https://developers.cloudflare.com/pages/configuration/custom-domains/) · [Nuxt sur Cloudflare](https://nuxt.com/deploy/cloudflare) | Bon compromis pour héberger le build statique avec des prévisualisations et un domaine personnalisé; le site est servi à la racine de son domaine. | Il faut configurer le projet Pages et remplacer la commande de build par une génération statique. Le SSR n'est pas nécessaire ici; des fonctions serveur ajoutent les quotas Workers. |

**Adéquation générale :** pour cette application à une route, sans API ni stockage distant, une génération statique suffit. Vercel est le choix le plus proche de la configuration existante; Cloudflare Pages offre des previews et GitHub Pages s'intègre directement au dépôt, au prix du chemin de base et d'un site public.

## Vue 3 + Vite et données

Oui, Vue 3 + Vite aurait aussi pu être hébergé sur GitHub Pages : Vite produit des fichiers statiques. Il faut configurer `base: '/<nom-du-dépôt>/'` pour un site de projet; les routes imbriquées en mode historique peuvent aussi demander une solution de fallback. [Guide Vite — GitHub Pages](https://vite.dev/guide/static-deploy.html#github-pages) · [Vue Router — mode historique](https://router.vuejs.org/guide/essentials/history-mode.html)

Changer de framework n'est donc pas nécessaire. Pour cette application sans backend, Nuxt statique est une option; le choix entre Vercel et un hébergeur statique dépend surtout du besoin de garder le runtime SSR.

Les campagnes restent dans IndexedDB du navigateur ([README.md](../../README.md), section « Données et sauvegarde »). Elles ne sont ni synchronisées ni sauvegardées par l'hébergeur, et `localhost` et le domaine déployé ont des stockages séparés : déplacer les données nécessitera l'export/import JSON. [WHATWG Storage Standard](https://storage.spec.whatwg.org/#storage-key)
