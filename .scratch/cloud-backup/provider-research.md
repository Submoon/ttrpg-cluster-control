# Cloud providers for Jump Cluster backups

Reviewed on 2026-11-13 for [GitHub issue #51](https://github.com/Submoon/ttrpg-cluster-control/issues/51). Repository baseline after fetching origin is `efd9b094634cf60d6c466f612df11cf9573b6b33`, equal to `origin/main`. This is a review of public provider documentation. The browser flows and account policies below still need live verification.

## What qualifies

A native integration lets a Warden select a writable destination in their existing storage account and upload the browser-generated Jump Cluster JSON directly. Each backup creates a separate dated file. A fresh browser can sign in, select the backup, and pass its original bytes to the existing restore workflow. The app can confirm the provider write, verify the destination's effective sharing before sending GM notes, and keep any account access as narrow as the provider allows. Local editing, autosave, download, and restore work independently. See the [scope decisions](analysis.md) and [portable restore ADR](../../docs/adr/0003-restore-complete-jump-cluster-backups.md).

The app's authorization and other users' access are separate checks. A narrowly scoped token may still write into a shared folder. An empty membership response only proves privacy when the provider documents a complete view of the relevant access. This review treats missing, partial, or inaccessible permission evidence as indeterminate.

## Comparison

## Google Drive

- Google Identity Services' token model lets a registered web client obtain a short-lived access token in the browser. Google Picker supports folder and file selection, and Google documents `drive.file` for files created by the app or opened through user selection. Use the selected folder ID as the new file's parent and download picked JSON as raw content with `alt=media`. Verify that the selected folder is accessible for both ACL inspection and upload with this exact scope, and that a separately uploaded valid JSON can be selected and restored in a fresh profile. Do not assume that Picker grants equivalent access to the My Drive root. [Token model](https://developers.google.com/identity/oauth2/web/guides/use-token-model) · [Drive scopes](https://developers.google.com/workspace/drive/api/guides/api-specific-auth) · [Web Picker](https://developers.google.com/workspace/drive/picker/guides/web-picker) · [Folder selection](https://developers.google.com/workspace/drive/picker/reference/picker.docsview.setselectfolderenabled) · [Parent folders](https://developers.google.com/workspace/drive/api/guides/folder) · [Downloads](https://developers.google.com/workspace/drive/api/guides/manage-downloads)
- Require a Warden-owned writable folder in My Drive and a complete owner-only permissions result. Drive documents permission inheritance and authorizes `permissions.list` with `drive.file`. Verify direct, inherited, group, domain and anyone access cases with a real account and refuse indeterminate results. Set `ignoreDefaultVisibility` to bypass a Workspace domain's default visibility on creation. Inherited permissions still apply. Drive does not document a parent-ACL precondition on the create request, so the privacy check is point-in-time and sharing changes can propagate independently. [File metadata](https://developers.google.com/workspace/drive/api/reference/rest/v3/files) · [Permissions list](https://developers.google.com/workspace/drive/api/reference/rest/v3/permissions/list) · [Inheritance](https://developers.google.com/workspace/drive/api/guides/manage-sharing) · [File creation](https://developers.google.com/workspace/drive/api/reference/rest/v3/files/create)
- Pre-generated Drive file IDs support retrying one logical create without duplicating it. A lost acknowledgement can leave a file present. Reconcile with that ID before reporting success or retrying, and keep earlier files. Register the web client and its JavaScript origins, configure Picker and Drive, and use authorized test accounts. A public launch needs the applicable Google OAuth and brand setup. `drive.file` is classified as non-sensitive. [Upload and retry](https://developers.google.com/workspace/drive/api/guides/manage-uploads) · [Picker setup](https://developers.google.com/workspace/drive/picker/guides/web-picker) · [Scope classification](https://developers.google.com/workspace/drive/api/guides/api-specific-auth) · [Production readiness](https://developers.google.com/identity/protocols/oauth2/production-readiness/overview) · [Brand verification](https://developers.google.com/identity/protocols/oauth2/production-readiness/brand-verification)

## Dropbox

- Dropbox documents authorization code with PKCE for public clients and accepts generated file bytes in its content API. A registered app requests content and metadata scopes appropriate to the flow. The App Folder option confines those operations to a dedicated subtree. Full Dropbox permits the requested operations throughout the account boundary. The app can browse API paths with metadata access and download the selected file after fresh authorization. The browser Chooser can independently return a four-hour CORS-enabled direct file link. Its folder-selection mode requires preview-link mode and does not confer write authorization. Saver offers destination selection but fetches a remotely reachable HTTP(S) URL, which a browser-local JSON Blob cannot supply. [OAuth](https://docs.dropboxapi.com/dropbox-api/docs/oauth) · [Browser requests](https://docs.dropboxapi.com/dropbox-api/docs/technical-reference/request-response-formats) · [Upload](https://docs.dropboxapi.com/dropbox-api/api-reference/user-endpoints/files/upload) · [Chooser](https://docs.dropboxapi.com/dropbox-api/docs/pre-built-components/chooser) · [Saver](https://docs.dropboxapi.com/dropbox-api/docs/pre-built-components/saver)
- The documented sharing APIs expose direct and inherited access signals, folder members, and links to the selected path or its ancestors. Their visibility depends on the caller and namespace. In particular, `list_folder_members` is unavailable with App Folder access. Verify that available metadata and sharing-link visibility can conservatively establish privacy before considering that option. Full Dropbox would need sharing-read access, complete checks for the intended account types, and an explicit decision on the broader grant. The folder-scoped Agent Filesystem uses backend credentials and is described as Private Preview in its authentication guide. [Sharing semantics](https://docs.dropboxapi.com/dropbox-api/docs/sharing) · [Folder members](https://docs.dropboxapi.com/dropbox-api/api-reference/user-endpoints/sharing/list-folder-members) · [Shared links](https://docs.dropboxapi.com/dropbox-api/api-reference/user-endpoints/sharing/list-shared-links) · [Agent Filesystem authentication](https://docs.dropboxapi.com/agentfs/docs/concepts/authentication)
- A unique operation path with add mode and automatic renaming disabled can preserve old files. On an ambiguous result, inspect the exact path and compare returned content metadata or hash before confirming or retrying. Keep the redirect URI registered and plan for Dropbox's development-user limits and production approval for standard API use. [Upload modes and result](https://docs.dropboxapi.com/dropbox-api/api-reference/user-endpoints/files/upload) · [Metadata](https://docs.dropboxapi.com/dropbox-api/api-reference/user-endpoints/files/get-metadata) · [Production approval](https://docs.dropboxapi.com/dropbox-api/docs/developer-resources/developer-guide)

## OneDrive Personal and work or school

- Microsoft documents SPA code exchange with PKCE and registered redirect URIs. Picker v8 has file and folder modes. Personal accounts use the consumer Picker configuration. Work or school uses a tenant-specific OneDrive or SharePoint host and resource tokens appropriate to the operations. The documented general Graph write scope, `Files.ReadWrite`, covers a signed-in user's files and includes files shared with that user on personal accounts. A Picker selection supplies item identifiers and leaves the token's permissions unchanged. The older `Files.ReadWrite.Selected` applies to legacy Office file handlers. The newer enterprise Selected permissions require an explicit resource assignment in addition to consent, with elevated permissions for that grant. [SPA authorization](https://learn.microsoft.com/en-us/entra/identity-platform/v2-oauth2-auth-code-flow) · [Picker v8](https://learn.microsoft.com/en-us/onedrive/developer/controls/file-pickers/) · [Picker schema](https://learn.microsoft.com/en-us/onedrive/developer/controls/file-pickers/v8-schema?view=odsp-graph-online) · [Graph scope reference](https://learn.microsoft.com/en-us/graph/permissions-reference) · [Selected permission grants](https://learn.microsoft.com/en-us/graph/permissions-selected-overview)
- Graph's sharing endpoint documents a complete effective sharing result for the owner and a caller-specific subset for nonowners. Prove ownership and write access to the selected folder, reject items owned or shared by others, and exercise direct links, inherited access, groups, and tenant visibility. Work/school and SharePoint do not return the `inheritedFrom` property, so its absence gives no privacy assurance. Keep organization-managed libraries out of scope unless effective access can be verified. Microsoft Graph's newer app-folder guide describes delegated `Files.ReadWrite.AppFolder` on home and work/school, while the OneDrive scope reference limits that delegated scope to personal accounts and the special-folder endpoint lists different minimum permissions. Test the fixed app folder, effective ACL read, create, and fresh-profile restore on each account type under the exact grant before relying on it. [Effective sharing](https://learn.microsoft.com/en-us/graph/api/driveitem-list-permissions?view=graph-rest-1.0) · [Permission representation](https://learn.microsoft.com/onedrive/developer/rest-api/resources/permission?view=odsp-graph-online) · [Graph app folders](https://learn.microsoft.com/en-us/graph/onedrive-sharepoint-appfolder) · [OneDrive scope reference](https://learn.microsoft.com/en-gb/onedrive/developer/rest-api/concepts/permissions_reference?view=odsp-graph-online) · [Special folders endpoint](https://learn.microsoft.com/en-us/graph/api/drive-get-specialfolder?view=graph-rest-1.0)
- Create in the selected parent using a unique operation filename and conflict behavior `fail`. A Graph upload session can report progress or the final DriveItem. Reconcile a lost final response by checking the exact target and verifying the content before retrying. For browser restoration, fetch the temporary `@microsoft.graph.downloadUrl` returned from authenticated metadata and treat it as a short-lived credential. Microsoft documents a CORS issue with using the authenticated `/content` redirect directly from browser JavaScript. Test public-client registration and tenant consent for each account type. [Upload sessions](https://learn.microsoft.com/en-us/graph/api/driveitem-createuploadsession?view=graph-rest-1.0) · [Browser downloads](https://learn.microsoft.com/en-us/graph/api/driveitem-get-content?view=graph-rest-1.0#downloading-files-in-javascript-apps) · [Supported account types](https://learn.microsoft.com/en-us/entra/identity-platform/v2-supported-account-types)

## Box

Box's Content Picker selects folders or files, and Box documents new-file creation under a parent and download by file ID. The standard OAuth code exchange uses an app secret. The documented route for browser components involves handing the client a resource-restricted token after downscoping an existing token. This suggests a credential-only backend could keep bytes on the browser-to-provider path. It would still add an application-operated authorization component. Before considering Box, prove browser download, registered origin and tenant access, and adequate read permission for the privacy check under the downscoped token. Check the owner, writable state, collaborators, and links through the ancestor chain, because Box inherits parent access. Reconcile conflicts through the exact dated filename and content evidence. [OAuth setup](https://developer.box.com/guides/authentication/oauth2/oauth2-setup) · [Token exchange](https://developer.box.com/reference/post-oauth2-token) · [Downscoping](https://developer.box.com/guides/authentication/tokens/downscope) · [Picker](https://developer.box.com/guides/embed/ui-elements/picker) · [Upload](https://developer.box.com/reference/post-files-content) · [Download](https://developer.box.com/reference/get-files-id-content) · [Collaborations](https://developer.box.com/reference/get-folders-id-collaborations) · [Inherited permissions](https://support.box.com/hc/en-us/articles/360043697254-Understanding-Item-Permissions)

## iCloud Drive and CloudKit

Apple supports manual uploads and downloads from iCloud Drive on iCloud.com and file access through Finder and Files. Apple also documents native iCloud document storage in an app-specific directory. CloudKit JS works with an app's own container and private database, which requires a CloudKit app, web services setup, and an API token. Private records and assets could serve a different app-container backup design. They do not provide a Warden-selected file destination in arbitrary iCloud Drive folders. Keep the portable JSON workflow for iCloud Drive. [iCloud Drive web files](https://support.apple.com/en-gb/guide/icloud/mmad632d1df2/icloud) · [Apple shared data technologies](https://developer.apple.com/documentation/technologyoverviews/shared-data) · [CloudKit JS](https://developer.apple.com/documentation/cloudkitjs) · [CloudKit container](https://developer.apple.com/documentation/cloudkit/ckcontainer)

## Other paths

- **Nextcloud and generic WebDAV.** Nextcloud documents authenticated listing, upload, and download with WebDAV, using a session or credentials such as an app password. A direct connection from the hosted editor needs a server that accepts the editor origin and the required CORS methods and headers. Use a unique path and verify conditional creation under `If-None-Match: *` on the target installation. Nextcloud's OCS Share API gives provider-specific share information, but generic WebDAV connectivity gives no portable assurance of complete effective access across shares, ancestors, group folders, and federated mounts. Consider this for explicitly configured deployments after proving a restricted credential and private folder. [Nextcloud WebDAV](https://docs.nextcloud.com/server/stable/developer_manual/client_apis/WebDAV/basic.html) · [Nextcloud Share API](https://docs.nextcloud.com/server/stable/developer_manual/client_apis/OCS/ocs-share-api.html) · [CORS standard](https://fetch.spec.whatwg.org/#http-cors-protocol) · [HTTP create precondition](https://www.rfc-editor.org/rfc/rfc9110.html#name-if-none-match)
- **pCloud.** OAuth and upload to a path or folder ID are documented. The upload API offers no-partial and rename-on-conflict options. Folder shares and public links have separate APIs. The reviewed OAuth docs do not describe selected-item grants, and evidence is insufficient for complete inherited privacy checks and private browser download across supported endpoints and account regions. Treat it as an exploratory candidate. [OAuth](https://docs.pcloud.com/methods/oauth_2.0/authorize.html) · [Upload](https://docs.pcloud.com/methods/file/uploadfile.html) · [Shares](https://docs.pcloud.com/methods/sharing/listshares.html) · [Public links](https://docs.pcloud.com/methods/public_links/listpublinks.html)
- **Proton Drive.** Proton ships an official CLI and provides SDK source and guidance for personal projects. Its SDK repository still describes official third-party support as pending. The CLI has a browser login for the installed client and an OS secret store. These sources do not establish a production-supported OAuth and selected-folder flow for a public browser app. Use portable JSON via Proton's client while that support is pending. [Proton SDK](https://github.com/ProtonDriveApps/sdk) · [Official CLI](https://proton.me/support/drive-cli) · [CLI authentication](https://github.com/ProtonDriveApps/sdk/blob/main/cli/README.md)
- **Provider UI or an OS-synced folder.** The Warden can use the ordinary JSON download and restore to transfer the file through any provider's web UI or a synced folder that their system makes available. A browser save picker can select a local file in supporting secure contexts. Completion establishes a local write. Remote sync, effective sharing, and recoverability on another device still depend on the sync client or provider. Keep ordinary download and file open available across browsers. [File System Access specification](https://wicg.github.io/file-system-access/) · [Picker availability](https://developer.mozilla.org/en-US/docs/Web/API/Window/showSaveFilePicker)

## Recommendation and verification

1. **Google Drive first.** It is the only candidate in this comparison with a documented browser-only path combining user-picked folders and files, a per-item scope, and permission inspection under that scope. Verify the whole sequence with an allowlisted test account before relying on it.
2. **Dropbox App Folder next if a fixed location is acceptable.** Require a proof that the available metadata and link visibility safely distinguish private and indeterminate destinations under the narrow grant. Full Dropbox is a separate, broader consent option. Choose it only if that trade-off is accepted and the sharing check is demonstrated.
3. **OneDrive Personal next if arbitrary folders matter more than a narrow grant.** Prove owner-only access on real personal accounts. If a fixed app folder is acceptable, evaluate that scope alongside Dropbox before expanding consent. Treat work/school as a separate qualification because tenant consent and access evidence differ.
4. **Box and configured Nextcloud** are candidates for a different operational model. Box needs a confidential token exchange. Nextcloud needs a configured server, browser CORS, and a deployment-specific privacy contract. Keep iCloud Drive, pCloud, and Proton Drive on the portable file path unless a supported browser flow and permission model are demonstrated.

Before any provider is announced as supported, verify with two isolated browser profiles and a disposable private test cluster. Create a dated backup, confirm its actual location, and reopen it in the second profile with no prior site state. Confirm that current and legacy files restore with GM notes, publication settings, and layout intact. Exercise direct sharing, inherited sharing, link and group access, permission lookup failure, cancellation, lost upload acknowledgement, retry, and previously saved copies. Use non-sensitive fixtures for shared-destination checks. Confirm the configured production origins and target account classes separately from the test-account round trip.
