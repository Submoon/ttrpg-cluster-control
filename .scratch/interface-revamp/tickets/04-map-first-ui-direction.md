## Candidate directions, not validated

- **Contextual workbench**: desktop with a small context bar, command palette, and temporary inspector; mobile with a full-area map and a details sheet with controlled heights.
- **Tool rails**: desktop with a compact mode/placement rail and on-demand contextual content; mobile with an accessible bottom action bar and catalog in a temporary panel.
- **Atlas hierarchy**: navigation/hierarchy establishes orientation, with an expandable map stage and contextual details; compare its discoverability against the map area it occupies. This is a third structural hypothesis, not a selected direction.
- Compare these directions using the same scenarios and states: area occupied on the map, icon learnability, and context preservation. Components and dimensions are hypotheses to test, not an established architecture.
- Show entry points for **future** search/filters and module navigation as separate items, without misleading buttons that imply those features are available or implementing those issues.
- Evaluate broadly adopted library surfaces against required interactions. Map-editing panels remain persistent/non-modal so independent map navigation is usable; a modal drawer making the map inert is not a valid alternative to that contract. Exact non-modal composition, focus cycle, scrolling, and retained drafts are prototype criteria. Genuine modal confirmations remain distinct.
