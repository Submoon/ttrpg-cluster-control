## Question

## Proposal to discuss

A visible policy for drafts versus canvas (exclude concurrent commands or merge selectively with an explicit conflict), a draft owner independent of panel mounting, and distinct feedback for draft/in-memory commit/durable save. Exclusion and merging are options for the user to decide; neither is settled.

## Resolution criteria

- Effects table for changing panel/selection/context/tool/theme, cancel/save, delete/create, import preview/cancel, and load/save/export errors.
- Preservation invariants covering all matrix operations, with necessary user scenarios and observed limits.
- Preview → commit → durable-save contract, retaining one persistence owner and accessible states.
- Explicit baseline and coordination conditions for reliability issues, preserving the implemented identity and compatibility behavior; do not claim reliability fixes are implemented or block planning on a reproduction outside scope.
- Record the human decision on strategy, without implicitly choosing a new durable data model.

## Blocked by

None: invariants and authority policy are independent of visual choice. Apply `grilling` and `domain-modeling`; fine-grained tool behavior will be adjusted after the prototype.

## Resolution

Resolved on 2026-10-13 through explicit human answers to Q1–Q6. This establishes the revamp's state-preservation contract; it does not implement the redesign or close its GitHub source. The [navigation contract](01-map-navigation-boundary.md) and [interaction contract](03-touch-keyboard-interactions.md) remain binding. Theme appearance, export palette, and library adoption stay with their own decisions.

### Draft authority and lifetime

- **Targeted exclusive editing:** an active draft owns edits to its entity and relevant dependencies. Reject conflicting canvas or other commands with an explanation and access to Apply/Cancel, before presenting a misleading editable preview. Pan/zoom and genuinely independent commands remain available. Do not lock unrelated entities or silently synchronize/overwrite draft fields. Dependency conflicts include commands that change the draft's valid host, placement, endpoint, field definition, or destructive footprint; determine them from actual effects, not merely the active panel.
- Apply the same policy to object, Orbit, Jump Route, chart-name, and field-definition drafts, including creation forms. Presentation is independent of the draft owner: hiding, remounting for responsive presentation, or changing theme must not destroy its content, target identity, validation feedback, or ability to resume. Maintain a visible draft indicator and reopening path when hidden.
- Drafts remain **session-only**. A presentation close is a hide; explicit Cancel/Discard ends only its designated draft. Apply ends it after successful validation and in-memory publication. This introduces neither persistent drafts nor a requirement to shelve drafts for multiple unrelated selected entities.
- Before leaving a modified draft for another selection/context or an incompatible editor, offer **Apply / Discard / Stay**. Apply uses the latest committed workspace, validates the candidate, publishes memory, then continues; it does not await successful durable saving. Discard abandons only the designated unapplied draft. Stay or validation failure keeps the draft, target, viewport, context, and tool. An unchanged edit session may leave without a prompt. No transition silently applies or discards work.
- An accepted effective context change returns to Navigation and restores that view's temporary viewport and valid selection under the existing contracts. A refused transition preserves the current context/tool. Selection is restored only when the entity still exists.

### Preview, application, and durable saving

- **Preview** is temporary and cannot enter durable data through cancellation, interruption, or another command. Normal valid gesture release, an explicit destination Confirm, or form Apply commits through the established validation boundary. Invalid targets/applications explain the problem without mutation; form validation failure retains the draft.
- **Apply in memory** validates a detached candidate before publication. Once published, it is committed map data and the form's editing session ends. Cancel, Escape, panel dismissal, and persistence failure cannot undo it. This changes the current draft acknowledgements that wait for durable success; it does not change the workspace schema or introduce undo.
- **Durable save** remains automatic, ordered, and owned by a single persistence boundary. Display Saving / Saved on this device / Not saved independently of draft and tool indicators. Saved means the latest applied snapshot reached local storage, not merely that a form closed. An older write result cannot falsely mark newer data saved.
- A durable-write failure retains the latest valid in-memory workspace, a persistent readable error, **Retry**, and **Export current JSON**. Retry saves that snapshot without replaying its originating operation or recreating an already-applied entity. A subsequent valid applied change can use the same ordered autosave boundary; status must truthfully reflect the latest data. Do not reload an older snapshot or roll back memory as an implicit response to failure.
- Current JSON export contains the applied workspace, including valid data whose local write failed, but excludes unapplied form drafts, gesture previews, and temporary viewport/selection/tool state. Export never auto-applies or discards a hidden draft; explain excluded draft work when necessary. Export/download errors are distinct from local-save errors and preserve the workspace and draft. Successful export does not prove IndexedDB saving succeeded. Palette and selection decoration in image exports remain the theme/export ticket's authority.
- Warn on voluntary browser departure or reload when modified drafts or applied data not yet durable exist, where browser capabilities permit. Drafts are not recoverable after actual session loss under this contract; a forced close/crash can lose them and unsaved memory. The warning makes this boundary visible without promising recovery that the browser cannot guarantee.

### Effects of user actions

| Action or outcome | Draft and command effect | Workspace, selection, and save effect |
| --- | --- | --- |
| Hide/reopen a panel or dialog; responsive rearrangement | Preserve its draft and feedback; reopening resumes it. | Preserve valid selection and viewport; do not create a workspace mutation. |
| Change theme | Preserve draft and tool intent. If an actual gesture interruption occurs, cancel only that preview under the interaction contract. | Preserve data, placement, selection, viewport, and save/error state. |
| Change tool / Return to Navigation | Preserve inspector drafts; cancel the uncommitted map action as specified by the interaction contract. | Preserve already committed edits, selection, and viewport. |
| Escape / gesture interruption / second-contact navigation takeover | Cancel the active gesture or operation preview first. Presentation dismissal may hide UI; never implicitly discard a draft. Escape on the map retains its established Navigation behavior. | No cancelled preview mutation and no undo of committed data; pinch preserves the active tool. |
| Conflicting command while a draft is active | Explain exclusion and expose Apply/Cancel; no competing edit preview or implicit draft change. | No conflicting mutation; independent navigation/commands remain possible. |
| Different selection, Chart Details, incompatible editor, or map context | Modified draft uses Apply/Discard/Stay; clean edit needs no prompt. | Refusal/invalid Apply retains target/view/tool. Accepted context changes restore view/valid selection and reset to Navigation. |
| Apply / valid gesture commit | Validate first; end the applied draft or preview at memory publication. | Publish valid detached memory, then save automatically. Draft application may continue its requested transition even if the write later fails. |
| Validation refusal | Retain draft, target, and feedback; invalid targeting keeps its tool active. | No candidate publication or durable write. |
| Explicit Cancel/Discard | Discard only the designated unapplied draft/action. | No rollback of applied changes and no clearing of an unrelated save failure. |
| Save pending / failed / retried | No reopening of an applied form or replay of creation. | Retain memory, truthfully show status, retry latest snapshot, and keep current JSON export available. |
| Prepare import / deletion / destructive field change | Preserve drafts during read-only preparation; resolve incompatible draft only when confirming. | Preserve current data until actual application; retain existing consequence review and domain validation. |
| Cancel preview / invalid import / other failure before application | Preserve draft and context; drop only the pending operation preview. | No operation mutation; distinct actionable error when appropriate. |
| Confirm preview | Apply the transition guard if required; recompute affected consequences after a draft Apply and renew review if they changed. | Apply only an accurate, confirmed, validated plan to the latest workspace; subsequent save failure follows the durable-failure policy. |
| Confirm deletion then create an entity | Remove references to deleted targets; no reuse of their old UI drafts or pending commands. | Clear stale selection/view-memory IDs after committed deletion. Creation uses fresh identity/defaults or explicit placement, with no copied deleted draft. |
| Export current JSON / SVG / PNG | No implicit draft Apply/Discard. | Preserve export scope and complete-map functionality; separate export error from saving status. |
| Load/recovery failure | Do not present an editable partial workspace; retain explicit retry/recovery feedback. | Keep baseline validated load, last-valid backup and durable-before-publication restoration semantics. |
| Voluntary departure/reload | Warn for modified drafts where possible; remaining session draft is lost if departure proceeds. | Warn while applied memory is not durable; restore only successfully stored validated data on reload. |

Import remains an explicitly confirmed, ID-remapped independent copy; it never silently merges or replaces current entities. Cascade deletion retains consequence preview and confirmation. Field-definition changes retain review of assignments that would be cleared and applicability behavior. Preparation must not force draft loss just to inspect these operations. If Apply changes a prepared plan's dependencies, its confirmation must describe the recomputed effects before commit; accepting an old preview is not authorization for a different destructive footprint.

### Preservation evidence and coordination conditions

The [preservation matrix](../analysis.md) remains the capability baseline. Relocation of a command may change presentation but must preserve its outcome, validation, cancellation, and touch/keyboard access. Before accepting implementation, require representative desktop, portrait/short mobile, virtual-keyboard, touch, keyboard, and single-pointer scenarios that demonstrate:

- An object, Orbit, Jump Route, chart-name, and field-definition draft survives relevant hide/reopen, responsive/theme/tool changes. Hidden ownership still excludes conflicting commands while independent operations remain usable. Show meaningful names/geometry/field values, not only empty forms.
- Concurrent Orbit inspector/canvas edits cannot overwrite one another, including changes through hosts, nested Orbits, attachments, and dependent field/endpoint operations. Explain exclusion before a conflicting preview. Preserve geometry validity and per-axis host-minimum adjustment with its independent notice.
- Apply/Discard/Stay handles valid, invalid, clean, and hidden drafts on selection/context changes. Refusal preserves context/tool; accepted context restores viewport/valid selection and Navigation. Gesture cancellation and pinch takeover preserve both inspector drafts and earlier committed edits.
- Application and durable saving have distinguishable outcomes. Simulated validation refusal publishes nothing; a durable-write failure keeps the applied map, ends its applied draft, retains global error, and permits current JSON export. Retry/latest autosave does not duplicate created objects, routes, or field definitions and does not report older data as the latest saved state.
- Cancelling or rejecting import, deletion, and field-definition previews preserves current work. Confirmation uses accurate dependencies after draft resolution; independent-copy remapping, destructive assignment review, cascade cleanup, fresh creation state, and stale selection removal remain valid.
- Durable reload, missing/invalid load, Retry, and Restore last valid backup retain baseline recovery behavior, with explicit missing/invalid-backup feedback. Recovery publishes only after durable replacement; ordinary edits publish validated memory before saving. JSON-copy import and local backup restore remain separate.
- JSON scope, layout and references, full-scene SVG/PNG export, catalog subtypes, hierarchy, object/native/custom fields and applicability, hosted/unoccupied/nested Orbits, attachment/detachment/order/axes/rotation/angles, systems, Jump Points, known/unknown route endpoints and positive jump levels remain usable under the new shell. Existing keyboard Delete protection, focus/accessibility feedback, and cancellation paths remain available.

These are required future demonstrations, not tests executed by this planning session. The prototype should show draft/error/cancellation states as well as layout; detailed bindings and appearance remain its work.
