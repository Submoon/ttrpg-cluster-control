## Question

Which form-width, grouping, action-position and display-label refinements make B's full-screen mobile Inspect usable in portrait and short landscape without changing its accepted panel or data contracts?

## Context and candidates

The [Astra global review](../research/astra-interface-review-2026-10-15.md) recommends using available name/notes width, reducing travel to Apply/Discard, distinguishing the seeded custom Session note from built-in notes, and replacing technical display spelling with established domain terms. These are recommendations, not a new domain taxonomy or permission to rename stored identifiers.

## Resolution criteria

- Obtain human decisions on form width/grouping and action placement, retaining full-screen mobile Inspect, reachable Hide, internal scrolling, validation feedback and usable short/keyboard-open layouts.
- Define unambiguous built-in/custom labels and user-facing catalogue terms without changing field identity, applicability, schema or interchange. Update the glossary only if a project-specific domain term or relationship is actually resolved.
- Preserve draft ownership, Hide/reopen, refused Apply, Apply/Discard/Stay, and the distinction between in-memory application and durable save/error/Retry.
- Name the targeted prototype and physical checks needed; do not imply unsupported prototype fields or simulated saves establish production parity.

## Resolution

2026-10-16 — The human explicitly confirms both decision rounds. Use a single form with visible sections adapted to the selected entity, one column on phones, full-width name/description controls, and optional side-by-side short controls on desktop. Keep mobile Inspect fullscreen and exclusive with Hierarchy; preserve internal scrolling and accessible top Hide.

Keep Apply / Discard changes in a persistent bottom bar. Hide retains the draft; Discard changes explicitly abandons it. Keep compact save status and reachable validation/save feedback with ordinary actions; show field errors beside their controls and provide access to the affected control from the feedback. Preserve the established in-memory versus durable-save distinction and error/Retry/export guarantees. Put Delete in a separate section at the end of the form, retaining the existing consequence review before confirmation.

Use Description for an object's built-in description. Custom definitions retain their own names, including Session note; visually distinguish native and custom values without changing identities, applicability or stored values. Existing readable catalogue/domain labels replace technical identifier spelling; preserve an Other object's custom subtype text. This does not introduce description properties for Jump Clusters or star systems, rename stored identifiers or establish new domain terms; no glossary or ADR change is needed.

The [audit and confirmed rounds](../research/inspector-form-refinements-2026-10-16.md) record the baseline, source references and prototype gaps. Prepare [Validate the responsive inspector form in the B prototype](17-prototype-inspector-form.md) to test desktop, portrait, short landscape and keyboard-reduced layouts, long text/catalogues, actions and draft/error flows. Creation of that follow-up does not begin code work. All existing baseline editing capabilities remain required for the final refactor; omitted or unsupported prototype controls are not accepted as feature cuts.
