## Resolution

Resolved on 2026-10-13 through the human answers above. This closes one navigation decision; it does not implement the redesign or resolve other decision tickets.

- **Scope:** retain distinct Jump Cluster and star system map views during the UI revamp. The continuous unified map and semantic zoom remain a separate effort; their navigation contract is not a prerequisite here.
- **Enter a system:** a click/tap on a system node directly opens its system map, except when the interaction is a movement gesture. Keyboard activation remains an equivalent entry path. A selection-then-Open step is not required by this redesign. Future multi-selection must coordinate this activation boundary in its separate effort.
- **Orientation and return:** keep the active Jump Cluster name and, in system view, the star system name visible in the UI context. Provide an explicit Return to Jump Cluster control usable by touch and keyboard. Its placement and appearance belong to the prototype; no hover or right-click is required to navigate.
- **View memory:** maintain separate temporary zoom/pan and last valid selection for the cluster view and each system view. Returning to a visited view restores that view's own state, including an object/Orbit or route selection as appropriate. Drop a stale selection if its entity no longer exists. Fit the map on a first visit. This memory stays outside durable workspace data and JSON exports; no reload-persistence requirement is introduced.
- **Draft boundary:** every context transition continues to pass through the existing unsaved-inspector/chart-name guard before switching views. Declining the transition leaves the current view and draft intact. Exact draft authority and Save/Discard/Stay policy remain in [Define revamp guarantees for drafts, selection, and saving](05-editor-state-and-preservation.md); this ticket does not settle them or allow automatic draft loss.
- **Functional context:** preserve existing cluster operations and system operations in their applicable view, as listed in [the preservation matrix](../analysis.md). The UI may relocate controls; catalog, route editing, hierarchy, details, file actions, and keyboard paths remain available. Their layout is a prototype question.
- **Future coordination:** the separate unified-map effort must coordinate context/orientation, activation versus editing/multi-selection, per-view restoration, and guarded transitions against this contract. This effort does not select semantic thresholds, coordinate conversion, or a new renderer. No new domain term or ADR was required.

The confirmed contract is sufficient to compare desktop/mobile prototypes. Remaining visual distribution and fine-grained tool behavior stay with the existing prototype and decision tickets.
