## Nuxt UI sizing decision and smallest adapter

Installed sources establish the following:

| Primitive | Actual behavior and consequence |
| --- | --- |
| `UDashboardGroup` | Provides `persistent:false` and `unit:'px'`. Its default persistence is true, so pass false explicitly. Use one stable group around the board/panel composition. |
| `UDashboardPanel` | Owns an ordinary stable slot subtree and a configurable resize-handle slot, but does not accept `side`; its internal `useResizable` therefore defaults to left. Passing an HTML `side` attribute cannot fix the right panel's delta direction. |
| `UDashboardSidebar` | Passes `side:'left'|'right'` to `useResizable` and puts the handle at the inward edge. It also renders desktop and menu slot branches, uses `lg` visibility defaults, and exposes no writable width model. A permanently closed menu plus empty content slot could avoid duplicate editors, but does not supply the accessible width setter needed here. |
| `UDashboardResizeHandle` | Supplies a styled separator primitive; it does not supply keyboard resizing or live range attributes. |
| Public `useResizable` | Exported by `@nuxt/ui/composables/useResizable` and the composables barrel. The declaration says `size:Ref<number>`, but installed JavaScript returns **getter-only** `currentSize = computed(() => ...)`, not the internal writable size computed. There is no supported external width setter. Its native pointer math accepts `side`, bounds, persistence and units; in LTR left delta is `clientX-initialX`, right delta is `initialX-clientX`. Right inward-edge dragging left therefore grows width. |

**Implementation-time correction:** the initial source analysis incorrectly treated the declared `Ref<number>` as proof of a writable public width. Writer B identified the getter-only return; coordinator and architect independently confirmed the installed JavaScript. That initial recommendation is withdrawn. DashboardPanel/Sidebar expose no width model, defaults are initialization values, keyed remounts violate editor lifetime, and synthetic events/private state are unsuitable. No supported library configuration supplies one width setter for both native pointer and accessible keyboard adjustment in this installed version.

Implement one small `WorkspaceResizablePanel.vue` adapter retaining **UDashboardPanel and UDashboardResizeHandle** for stable composition, appearance and separator semantics, with **one application-owned session width ref** controlling real pointer/touch and keyboard resizing. This narrowly justified exception replaces only the unavailable controlled resizing seam, not the sidebar/editor design. Empty the Panel's own resize-handle slot so its internal native controller never competes. The adapter must actually resize; a fixed-width `resizable:false` substitute remains unacceptable. Keep UDashboardGroup explicitly nonpersistent with pixel units; the custom width ref likewise has no storage.

The wrapper API is `panel:'hierarchy'|'inspector'`, `side:'left'|'right'`, `compact:boolean`, `visible:boolean`, `label:string`; default slot owns the existing editor once. Existing stable outer panel IDs/roles and close controls remain MapEditorLayout's responsibility. Hide/disable its resize handle in compact mode while preserving the same session width ref. There are no cookie/localStorage/workspace writes.

The minimal controller uses Pointer Events for mouse/touch/pen: record pointer ID, starting client X and actual width; capture the pointer on the handle; apply signed horizontal delta (LTR left: current-start; right: start-current), clamp to current bounds, and update that one width ref. Keep `touch-action:none` scoped to the handle, stop the resizing sequence from reaching the map, and ignore unrelated pointers. End/release capture and clear state on pointerup, pointercancel, lostpointercapture, disable/hide, breakpoint change and unmount. Cancellation stops further size changes; it need not undo the user's already visible width adjustment. Respect direction if inherited RTL is supported, or keep the current LTR contract explicit. Double-click/reset returns to the bounded default without remounting.

Give the inward-edge separator `tabindex=0`, accessible name, `aria-orientation=vertical`, `aria-controls`, and actual min/max/current pixel values. ArrowLeft/ArrowRight follow the visible edge (right panel: left grows; left panel: right grows), with a small fixed step and larger Shift step; Home/End set bounds. Clamp through the same application width ref used by pointer input. Mouse/touch drag and keyboard adjustment must produce the same real width. Defaults can be about 300px hierarchy / 360px Inspect; derive useful desktop maxima from actual board width and leave a usable center when both are open, rather than allowing two maximized overlays to cover it. Clamp desktop width to current bounds without treating fullscreen compact width as a new remembered desktop width. Hide/reopen and desktop→compact→desktop retain session dimensions without remounting editors. Reload may reset dimensions.

This bounded exception is preferred over modifying installed files, synthetic document mouse events, private Vue setup-state access, keyed remounts to change defaults, or duplicating sidebar/mobile content. Retain Nuxt UI buttons/popovers/slider/theme controls and the established application FocusScope adapter. Verify actual right-edge direction, touch/pointer cleanup and keyboard behavior at runtime before claiming adoption is complete.

## Actual obstruction measurement and camera invariants

`WorkspaceMapCanvas` currently measures only `feedbackElement` when explicit Fit is called and otherwise fits the whole SVG. Its first-visit branch calls the raw map handle directly. Extend this seam so **both first-visit Fit and explicit Fit/recovery use all actual visible obstructions**: map chrome, hierarchy, Inspect, Dock, zoom and feedback. Keep `feedbackElement` compatible during integration; avoid measuring the same footprint twice.

Use an enclosing board marker plus `data-map-obstruction` on actual visible overlay footprints, scoped to that board. Do not mark a full-board wrapper containing empty transparent space as an obstruction. Hidden, disconnected, inert or zero-area elements do not obstruct. Clip measured rectangles to the actual SVG client rectangle. Infer no width from declared panel defaults and no height from fixed header/footer offsets. The group/container sizing, safe-area padding, responsive placement and overlay resizing determine these measured rectangles.

Compute a usable axis-aligned rectangle disjoint from the clipped obstructions (for the small bounded set, enumerating candidate obstacle/client edges and selecting the largest positive-area unobstructed rectangle is sufficient). Where layouts offer several candidates, favor a useful central area deterministically. Convert the chosen rectangle's client-space corners through the SVG's inverse screen CTM, then normalize in existing SVG viewport units. This preserves viewBox/letterbox behavior; client pixels are not scene coordinates. Invalid/unavailable geometry must retain the existing camera rather than substituting a false fixed rectangle. A tiny reusable conversion helper in map-zoom is allowed to avoid its present duplicate CTM arithmetic; preserve existing public defaults/callers.

Layout may use ResizeObserver/viewport measurement to keep tool/panel clearances current. Such measurement must not call Fit or setViewport. Fit reads current geometry on demand; panel open/close, resizing, theme changes, recovery expansion or reflow never silently refit/reset a visited map. First visits fit after map and overlay layout are ready; revisits restore accepted memory. Existing immutable source map-key checks and accepted/refused context boundaries stay intact. Representative targets must be ordinarily hit-testable after Fit at short height; SVG bounds alone do not establish this.
