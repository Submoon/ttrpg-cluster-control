## Genuine prerequisites and independent paths

1. **Early product integration** must precede claims about real persisted journeys. It restores creation/load/resume on the production root, keeps the SSR shell/client maps, and proves a real save/reload. Existing baseline capability tests remain useful, but current root tests cannot certify the memory sample.
2. **Application acknowledgement and truthful save recovery** must precede a dependent slice claiming that Apply ends its form or continues navigation during a forced write failure. Include latest-memory Retry, ordering/stale completion, persistent recovery feedback and applied-current JSON in that small demonstrable slice. Retain load Retry as a separate action and the stronger durable-first backup-restore contract. Fields creation must not replay after failed persistence.
3. **Session draft/transition ownership** must precede dependent full editor flows and destructive confirmation. Demonstrate at least one real dirty draft surviving Hide/reopen/reflow, a clean transition without prompting, valid/invalid Apply, Discard/Stay, hidden ownership exclusion and an unrelated permitted command. Subsequent entity-specific slices extend the same contract and test it; do not defer exclusion correctness to a final test ticket.
4. **Map intent arbitration** enables safe placement/manipulation, but does not depend on complete Fields or every Inspector. Establish both-map Navigate/Select/Move, keyboard activation, view-only pan and cancel/suppression first. Then creation targeting, route progress and manipulation can be bounded vertical slices. A route-origin state must remain distinct from a canceled pointer preview.
5. **Hierarchy and accessible alternatives** are complete targeting paths, not optional polishing. Each creation/manipulation slice delivers keyboard and single-pointer equivalents for its results, with Confirm/Cancel and meaningful target indication. Do not make accessible outcomes depend on a later universal accessibility ticket.
6. **Fields navigation/creation** may precede advanced destructive impacts once session/Apply contracts exist. Native/custom object values do not have to wait for the whole Fields redesign: retained definitions and baseline commands can supply them. Conversely, Fields consultation need not wait for every object Inspector control. Their genuine joint prerequisite is refreshed impact handling when a definition change conflicts with an object draft.
7. **Deletion, destructive Fields changes and import** share latest-plan authorization and stale-ID cleanup. A first real reviewed-delete slice can establish this narrow contract; later operations apply it. Import need not await image export, and image export need not await deletion or Fields completion. If overlap is only the file menu or shared workspace module, coordinate ownership rather than add a blocking edge.
8. **Theme/palette/local icons** can progress from early shell integration alongside tool and form work. Image palettes require the defined common tokens and applied-state boundary; they do not require all theme accessibility evidence to be completed first. Every later surface still verifies actual contrast, portal palette and retained session state.

Avoid a cycle of “shell waits for all forms, forms wait for draft state, draft state waits for final tools, tools wait for shell.” Use a narrow working shell with retained commands, then one representative draft/apply path, then additive forms/tools against stable contracts. Prefer 18–20 bounded, independently demonstrable slices to a smaller set of omnibus “state,” “all forms,” “all tools” and “all tests” tickets. A prefactor should be a small enabling change with a concrete behavior proof, or an explicit expand–migrate–contract exception if evidence really requires a mechanical wide refactor; current evidence does not require one.

## Guarantees to embed in every affected ticket

- Nuxt UI reuse is the default for suitable controls, menus, forms, overlays and panel composition. Configuration/slots/adapters precede bespoke equivalents; record only the smallest justified exception. The prototype implementation is not pre-approved architecture.
- Retain current database/marker/MIME identity, schema version, supported decoding, references and authoritative validation. No persistent drafts, new migration, previous-marker fallback, account or remote sharing is introduced.
- Separate applied workspace, durable snapshot, session draft, view/selection, tool progress and gesture preview. Theme/reflow/hide cannot implicitly apply or discard; persistence failure cannot roll back valid applied memory; Cancel cannot undo a completed creation or clear an unrelated save error.
- Cover desktop and automated portrait/landscape/touch/reduced-height behavior where applicable. Ordinary hit-tested controls, focus, named/visible non-color cues, actual usable map/form area and local resources belong to feature acceptance. Android **Chrome only** supplies targeted real OS-keyboard, safe-area and physical-gesture evidence; historical Firefox findings do not impose Firefox support or certify Chrome.
- Map each slice to its relevant specification stories and B1–B10 families, plus retained capability regression cases. Final integrated evidence consolidates these results; it cannot be the first test of crosscutting guarantees.
- Image output covers both maps, SVG/PNG, active light/dark and export-only print light, the applied system title, long/off-screen content and clean full bounds. Independently inspect standalone output and preserve live state even during drafts, previews and failed saves.

## Mandatory final cleanup and evidence ordering

The cleanup is the final numbered ticket, blocked by every other implementation/evidence leaf. Earlier slices may remove immediately obsolete code as needed, and must isolate product integration early; the final ticket closes remaining experimental and documentation debt.

It should consolidate current product/build/test/developer documentation, archive superseded chantier material with a concise discoverable index, and retain useful accepted decisions and evidence provenance (source hashes, runtime/device identity, limitations and links). “Clean documentation” does not mean deleting the specification, accepted rationale or inconvenient failures. Preserve closed decision paths or provide working archival links.

Remove or disconnect experimental routes/flags, product imports, comparison shells, unused assets, fixture wiring and dependencies/configuration **only after proving they are unused by the real product**. Reusable validated fixtures may remain tests-only; retained research archives must not be production dependencies. Keep shared Nuxt UI providers, SSR/client map integration, geometry/domain modules and required local icons. Do not wipe browser storage or change schema/identity as cleanup.

The final ticket includes **post-cleanup** typecheck/build, relevant integrated parity/resume/export smoke, verification that production cannot reach/load the disposable comparisons, and final compiled-production resource/startup/overlay/map measurements against a comparable preserved baseline. Earlier performance evidence is provisional if comparison code remains. Do not schedule a supposedly final production-cost measurement before the ticket that removes its comparison imports. Missing baseline/device arms remain explicit limitations, never zero-cost or passed results.

No tests, builds or device checks were executed by this planning audit. The final proposal still needs independent DAG, story/B-family coverage, ticket-size and final-cleanup-order review before the human approval gate.
