## Responsibility and exception inventory for the adoption conversation

- **D3/SVG maps and domain:** application-owned geometry, commands/validation, session drafts, persistence and interchange remain outside the visual library's responsibility.
- **Persistent inspector envelope:** custom desktop non-modal and compact fullscreen composition preserves map interaction and draft ownership. B uses Nuxt UI form controls and feedback within that envelope; a default modal cannot replace desktop independent navigation.
- **Dock, hierarchy and catalogue:** bespoke map-specific composition, nested hosted Orbits and domain glyphs retain explicit labels/targets. Nuxt UI remains available for compatible controls and surrounding surfaces. Existing native buttons are a scoped adaptation inventory, not proof that a library alternative was exhaustively benchmarked.
- **Fields:** B now uses a Nuxt UI modal with application-owned list/detail/edit state and the shared business-value presentation. The earlier native Fields exception in historical measurements describes the old capture and the retained baseline, not the current B modal.
- **Add and confirmations:** the current Add chooser uses the actual Nuxt UI Popover trigger; application state owns placement, cancellation and gesture arbitration. Nuxt UI modals present reviews while the application owns exact impact plans and guard decisions.

Adapt the library first and document targeted exceptions as already agreed. This dossier recommends preserving that responsibility boundary; it does not substitute for the later human adoption decision.

The subsequent human decision makes the final interface **Nuxt UI by default**. The bespoke surfaces above describe the prototype, not automatically approved production exceptions: reassess dock, hierarchy, catalogue and persistent editor envelopes against suitable Nuxt UI components/configuration/slots. Keep only the smallest justified exception and retain compatible Nuxt UI controls. Maps, domain state and persistence remain application responsibilities; ordinary interface controls do not acquire an exception merely by presenting domain data.
