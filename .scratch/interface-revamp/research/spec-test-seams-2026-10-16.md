## Proposed seam

Use **one primary behavioral seam: the real, integrated browser editor through Playwright**. Start or import a workspace, operate accessible controls and actual map input, observe the resulting map/forms/status, inspect downloaded files, and reload to observe durable results. Parameterize meaningful variants of those journeys rather than add a test layer for each component, workflow composable, D3 renderer and library primitive. Test external behavior, including refusals and unchanged outcomes, rather than component names, internal refs or exact CSS structure.

Keep the existing small lower layer for supported schema restoration, independent-copy interchange and storage transaction invariants when the browser journey cannot economically enumerate malformed or compatibility inputs. Those tests can continue using the existing Playwright runner; there is no separate unit-test command or Vue component harness in the inspected package. No new test-only application API, global command bus or production diagnostic endpoint is needed. Fault setup may use browser-platform interception already demonstrated in the repository; assert the visible result through the application.

Keep physical-device, keyboard/screen-reader and independent exported-file inspection as explicit evidence gates where automated Chrome viewport/input simulation cannot establish the outcome. They use the same user-facing seam rather than inventing new architecture.

## Existing commands and an important route limit

[package.json](../../../package.json) defines `npm test` as `npx playwright test`, `npm run typecheck` as `npx nuxt typecheck`, and `npm run build` as `npx nuxt build`. [playwright.config.ts](../../../playwright.config.ts) discovers `tests/`, uses the list reporter and base URL `http://127.0.0.1:3100`, and starts `npm run dev -- --host 127.0.0.1 --port 3100`. It declares no browser/device project matrix. A focused existing-runner invocation is `npm test -- tests/workspace-recovery.spec.ts`; choose affected files for implementation, then run the relevant integrated preservation suite. Typecheck/build complement behavior checks; they do not prove it.

**The current root route is a disposable preview.** [pages/index.vue](../../../pages/index.vue) defaults `/` to `PrototypeWorkbench`; only `?variant=baseline` mounts [BaselinePage](../../../components/BaselinePage.vue), which owns the actual `useLocalWorkspace` integration. Existing `tests/*.spec.ts` navigate to `/` and expect baseline welcome/forms. They are useful preservation prior art, not evidence that the current route passes that suite or that the preview is persisted. The implementation must deliberately target the real integrated product route, update selectors for accepted presentation and retain behavioral assertions. Any interim baseline check must explicitly select its route and disclose that shared-renderer changes remain present. Do not promote the prototype or mechanically redirect all tests to it.

The package browser gate starts a development runtime. A compiled-production smoke is separately necessary for Nuxt UI hydration, menus, portals and modal geometry: the [Fields production placement correction](fields-modal-position-2026-10-16.md) demonstrated a development/production distinction. No additional script or ready-made production configuration is claimed here. Coordinate owned ports/output directories; no runtime was started for this report.

## Narrow lower-layer regression and fixture policy

1. **Supported restoration and interchange:** retain the existing pure Playwright tests for accepted route/layout forms and applicability values; check malformed candidates, detached validation, independent-copy remapping/reference integrity and exported system/cluster scope through domain APIs already used by the tests. No schema/marker/database migration is introduced.
2. **Geometry/domain invariants:** retain host-minimum per-axis correction, nested-host/deletion cleanup, per-host order and Orbit/object-placement regressions when touched. Prefer the existing UI-plus-download/reload tests; add a direct domain case only for a concrete branching invariant that cannot be diagnosed economically at the browser seam. Avoid re-testing every Vue condition as a pure function test.
3. **Storage atomicity:** retain the real-browser storage adapter transaction-abort, invalid-current/backup and restoration tests. They are necessary complementary evidence for durable-before-publication recovery; add end-to-end visible-save cases from B7 rather than replacing atomicity tests with simulated prototype statuses.

Existing root tests usually create their small workspace through UI and build import fixtures inline; [helpers.ts](../../../tests/helpers.ts) centralizes catalogue, file/download and world-coordinate input helpers. There is no inspected reusable `test.extend` fixture layer. A helper extraction inside tests is sufficient if duplication warrants it; a new application seam is not required.

The disposable rich samples are useful scenario material: [dense Fields helper](../../../components/prototype-fields-fixture.ts), [dense inspector helper](../../../components/prototype-inspector-fixture.ts), and the normal Workbench seed. Do not use production query flags or a sample seed as the persisted product data source. Translate an explicitly selected rich sample into valid import/setup data using the real schema/codec, and record its identity/counts. The [Fields fixture proof](../device-preservation-lab/artifacts/fields-flow-2026-10-16/final-fixture/README.md) matters because three globally ordered seeded Orbits previously violated host-relative ordering; validators must not be relaxed to make tests pass. Cover ordinary plus rich/long-content setup and preserve existing user storage through fresh isolated browser contexts.
