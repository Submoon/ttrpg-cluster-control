## State ownership and transitions

Use a small set of component-owned refs/reactive values; no store, generic state-machine package or durable drafts:

| State | Contract |
| --- | --- |
| Presentation | open/hidden, screen `list | detail | create`, selected definition ID or null; first opening is list, subsequent openings resume a valid state. Desktop renders list and detail together; an initially unselected detail can show a short choose-a-definition prompt. |
| Existing definition draft | One owner ID, editing flag, detached name/options/applicability values and baseline snapshot for semantic dirty comparison. Read-only until Edit. Back and Close retain it; selecting the same ID resumes it. Do not keep a dictionary of several shelved drafts. |
| Creation draft | Detached name/type/options plus baseline defaults. New uses the established target-change guard if another modified draft exists. Hide preserves creation; explicit Cancel ends only this creation and returns to list. |
| UI memory | List scrollTop, selected row/focus target, actual Fields/Manage opener; optionally content scroll for resumed detail. Restore after DOM update. Selection/identity and draft values are authoritative; do not infer them from DOM position. |
| Pending flow | One requested transition (`select ID` or `create`) and one pending command/review. Apply can suspend a target change until validation, review and memory acknowledgement complete. Stay, refused validation or canceled review must not run the queued transition. |
| Feedback | Validation/error, pending destructive review and conflict. Hiding, resizing, theme/layout changes preserve meaningful feedback. Keep a visible Fields draft indication/reopening path when hidden. |

Determine modified work from normalized semantic values, not merely the editing flag. Existing option order is meaningful; scope equality uses `sameCustomFieldApplicability`. New empty text/default-type creation is clean; meaningful name/type/options changes are dirty. Beginning a clean edit must not trigger a discard prompt on switching targets.

Back returns to list with row highlight/focus/scroll, retaining the current draft. Selecting another ID or New uses Apply/Discard/Stay when dirty; Discard abandons only the current draft then continues; Apply continues only after actual valid field application; Stay/invalid Apply retains the prior target/screen/work. Successful creation selects the actual newly created ID and opens read-only detail. Successful selected-definition deletion clears that ID, returns to list and focuses a valid nearby row, falling back to the list heading/New. Never implicitly select Atmosphere.

Close is hide, not Cancel. Capture an explicit opener when possible, otherwise document.activeElement before showing the modal. Restore focus to that actual still-connected control; use a sensible B Fields fallback if it is gone/hidden. List/detail focus moves must not scroll back through the entire catalogue. Use one modal boundary; nested confirmation/conflict regions must be reachable in the native dialog's top layer, not a separate modal mounted behind it.

## Exact command and acknowledgement seam

Keep these existing payloads unchanged, importing their types from the pure model:

```ts
createCustomField: { name: string; type: CustomFieldType; options: string[] }
saveFieldDefinition: {
  fieldId: string; name: string; options: string[];
  applicability: CustomFieldApplicabilityTarget[] | undefined;
}
removeFieldDefinition: string // custom definition ID
resolveInspectorConflict: 'apply' | 'discard' | 'stay'
```

The new component keeps the existing emitted names: `create-custom-field`, `save-field-definition`, `remove-field-definition`, `clear-error`, `resolve-inspector-conflict`, and `open-change`. It accepts the existing workspace/saving/saveError/saveRevision/inspectorConflict/error inputs plus action layout/enabled. An optional small state-change event can expose flattened screen/selected ID/draft/dirty/review values to the prototype state peek and hidden-draft indicator; do not expose raw drafts as workspace data.

Expose the parent's existing `open(...)`, `isOpen()` and `cancelImpactReview()` methods. Allow `open` to receive an optional actual opener. A simple `hasModifiedDraft()` read method supports targeted exclusion of conflicting whole-workspace replacement while Fields is hidden. No generic persistence API is added.

**Acknowledgement sequence:** record the pending operation and pre-application selected/known IDs **before emitting**. A parent `saveRevision` advance is the success acknowledgement after memory publication. Only then reset the applied draft, select the newly created ID or return after deletion, and finish a queued target transition. Do not equate `saving=false`, an emitted request, a toast or a cleared error with successful application. B's simulated durable failure after acknowledgement must not resurrect the already-applied draft or undo memory. Domain validation errors leave values/target/queued transition unapplied and show the error.

**Destructive/guarded Apply:** compute affected assignments from the latest workspace and the draft; show named impacts, then require explicit confirmation before emitting the existing destructive command. Recompute at confirmation. Compare a stable signature of `{ operation, fieldId, currentDefinition, normalizedRequestedUpdate, affectedAssignments }`, sorting assignment records by object ID and including their object ID/name, system name and value. If it differs, replace the preview and require confirmation of the updated effects. A small relevant-content signature is enough; no global revision system is needed. Canceling review retains the edit draft and cancels a pending target switch.

If the parent raises inspectorConflict, keep the field draft and its pending context. Route the existing conflict choices to `resolveGuard`. Parent object Apply invokes the originating manager's `cancelImpactReview()`: clear the old impact/operation acknowledgement state, preserve the field draft, and require renewed field review before application. Never treat object Apply as acknowledgement of the field request. Object Discard retries the parent field command using current committed data; only the field revision acknowledges success. Stay preserves both drafts, with no deferred target change firing later. Invalid object Apply keeps the conflict/error and both drafts. A queued field-target switch may continue only after its field application is actually acknowledged; cancel/stay clears its intent.

While a hidden modified Fields draft exists, block a confirmed whole-workspace replacement/import that would invalidate its target, explain the conflict and reopen Fields with Apply/Cancel available. Import preparation/cancellation preserves the Fields draft and publishes nothing. The bounded prototype can require explicit retry of replacement after resolving Fields; document that limitation. It must not silently discard, implement a weaker discard-only target transition, or mutate the refused snapshot. This is targeted exclusion, not a rewrite of import. Independent object edits/navigation remain available; assignment changes invalidate any old destructive preview through the relevant-content check. If a target disappears through an unsupported external replacement, show explicit stale-target feedback and preserve the orphan draft for resolution, rather than silently deleting or applying it. Do not claim full unrelated import parity from this prototype.

## Two focused variants and dense data

Host both on the existing B route, for example:

- `/?variant=B&controls=dock&fieldsActions=header`: **Header commands**. Back/title/Close plus the immediate Edit or Apply/Cancel row remain above a single scrolling form/assignment area. This keeps command identity close to the selected definition and avoids competing bottom bars; short landscape has less content height.
- `/?variant=B&controls=dock&fieldsActions=footer`: **Bottom commands**. Back/title/Close remain at top; primary actions occupy a separate bottom band above the visible keyboard/safe area, outside scrolling assignments. This improves thumb reach but requires actual keyboard geometry evidence.

Recommend header as the initial default; keep footer as the materially different comparison. They share the exact accepted flow/state. Query-only layout switching uses router.replace with existing query parameters preserved and **must not reseed or remount**. Put the clearly labeled dev-only floating comparison control inside the Fields modal's operable area; the existing page switcher is inert behind a native modal. Reserve its space and stop comparison-arrow propagation to global A/B/C shortcuts. Never intercept arrows in inputs, textareas, selects, contenteditable controls or other keyboard-operated widgets. Production hides comparison chrome, while explicit shareable query variants may render in the preview.

Use `fieldsSample=dense` only at initial B memory-workspace construction. Retain the normal seed unchanged otherwise, including A/C and `variant=baseline`. Add about 32 named custom definitions cycling the four supported types, including long names and scopes; assign valid sample values to existing catalogue objects across systems so assignment lists exceed a phone viewport. Include values stored outside applicability and used native/custom options. Report the actual assignment count; do not pretend UI-only invented rows are domain assignments. Prefer existing seed objects over unrelated new geometry. Fixture changes require reload or an explicit discard action; changing fieldsActions alone never replaces it. No IndexedDB/localStorage reads/writes and no changes to stored JSON/schema.

## Addendum: human-directed Nuxt UI modal envelope

The human subsequently requested a Nuxt UI dialog with a maximum size. Adapt only the new B component to **UModal**; this supersedes the native-dialog envelope recommendation above without changing its state/events/domain contracts. Inspected installed `@nuxt/ui` 4.11.3 `dist/runtime/components/Modal.vue`/`Modal.d.vue.ts`, generated `.nuxt/ui/modal.ts`, and Reka's `DialogContentModal.vue`/`DialogContentImpl.vue` in the ignored preview-build dependencies. Current new prototype still used native showModal/close and a dialog DOM ref at inspection; replace those native-specific calls rather than wrapping a native dialog inside UModal.

- Use controlled `open`, the **content slot**, a portal, compact fullscreen, and an explicit desktop maximum wide enough for two columns. Nuxt UI's default desktop `max-w-lg` is too narrow; override via `ui.content`. Its nonfullscreen envelope already supplies centering/translates and a maximum height. Remove conflicting native margin/position/transform/backdrop CSS, and avoid adding a second translate-based centering layer.
- `#content` replaces Nuxt UI's default header/body/footer wrappers: its body overflow rule does **not** automatically provide a scroll container for custom Fields markup. Retain a constrained flex/grid content region with min-height zero and one intentional form/list scroller; keep the compared command bands outside long assignments. Place theme classes and diagnostic data attributes on the actual UModal DialogContent via its content/ui seam, not an inert component wrapper. Supply UModal title/description so its hidden accessible title/description remain defined alongside the visible heading.
- Keep all existing component-owned refs **above** the content subtree. Allow `unmountOnHide` to remove presentation safely; do not move draft/creation/review state into slot-local children. With `unmountOnHide=false`, retained DOM still needs accurate hidden/focus behavior; it is not a substitute for state ownership. Layout/theme/compact changes never key/remount the owning component.
- Route `update:open(false)`, custom Close, outside interaction and Escape through explicit handlers. Content supports `onEscapeKeyDown`, `onInteractOutside`, `onOpenAutoFocus` and `onCloseAutoFocus`. Prevent default dismissal when an inner pending review/transition consumes Escape or an object conflict must remain. Priority remains conflict handling → cancel current impact review → Stay on the target-change guard → hide Fields, without implicit draft discard. Outside/Close may hide ordinary detail/creation while preserving work; they must not bypass an unresolved conflict. Use controlled state rather than an unconditional v-model assignment that closes before these checks.
- Restore the **captured actual opener**, not an assumed UModal trigger: Fields/Manage are external and no default trigger slot exists. Prevent default close autofocus when managing it explicitly; restore after leave/focus-trap release, not merely the next tick while the trap may still be active. Reka's force-mounted-content path restores its own remembered trigger on presence changes, so verify both openers in the chosen unmount mode. Replace the old dialog DOM ref's querySelector/focus calls with a real content element ref or a narrowly scoped data selector.
- Keep the impact review, transition guard and object-conflict region **inside the same UModal content**. Stop local comparison/Fields keyboard events reaching Workbench's global A/B/C shortcuts; the existing role=dialog checks still need verification after migration. Check Escape priority, keyboard focus containment, header/footer action reachability, hide/reopen state and real-opener focus in both compact and desktop modes. UModal maximum sizing alone does not establish virtual-keyboard or physical-phone acceptance.

This is an authorized container adaptation, not another human decision or a shared-baseline/global-CSS change. Luna remains the only application writer; dual independent review and actual runtime evidence remain required.
