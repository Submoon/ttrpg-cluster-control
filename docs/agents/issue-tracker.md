# Issue tracker

This repository uses local Markdown files for issues. Do not use GitHub Issues, GitLab Issues, or another remote tracker for this repository's planning tickets.

## Location and structure

- Store each effort under `.scratch/<feature>/`.
- For Wayfinder, use `map.md` for the canonical map and `tickets/<slug>.md` for its child tickets.
- Give each map and ticket a human-readable title. Use relative Markdown links whose link text is the ticket title.
- Put `title` and `status` in YAML frontmatter; tickets also have `label`, `type`, a parent-map link, and optional `assignee`. Use `label` only for the `wayfinder:<type>` value. Triage roles are separate; see `docs/agents/triage-labels.md`.
- Append triage notes and agent briefs under `## Comments`; start each with `> *This was generated by AI during triage.*`.

## Ticket lifecycle

Use these exact `status` values:

- `open` — new, unclaimed, or available for work. This is the initial status.
- `in-progress` — claimed and actively being worked.
- `blocked` — work cannot proceed until a dependency or outside decision is resolved. Record the blocker; return to `open` when it clears unless work resumes immediately.
- `closed` — resolved or ruled out of scope. Record the outcome in `## Resolution`.

An open ticket without an assignee is unclaimed. Add an assignee and set `status: in-progress` before working it. A blocked ticket is not on the frontier. Close the map when its destination is reached.

The Task Board maps `open` to planned, `in-progress` to in progress, `blocked` to blocked, and `closed` to done. Keep triage roles out of `status`; for example, `wontfix` is a triage role, while `closed` is the lifecycle status.

## Wayfinding operations

- Keep the map as an index: closed decisions go in `Decisions so far`; do not list open tickets there.
- Local Markdown has no native blocking relation. Record dependencies in a `## Blocked by` section with links to the blocking ticket titles.
- Record a resolved ticket's answer in `## Resolution`, set `status: closed`, and add a concise linked gist to the map's `Decisions so far`.
- Link research/prototype artifacts from the relevant ticket rather than pasting large artifacts into the map.
